# Stage 10 - Formwork Pilot Operating Handbook v1.0

## Pilot objective

Prove that one professional Formwork Engineering Virtual Firm can operate the full controlled workflow from client intake through proposal, delivery, review, issue, billing, AI assistance, and private network signalling.

## Operator sequence

1. Open the workspace.
2. Confirm API and Ops readiness.
3. Create or select pilot tenant and firm.
4. Confirm Principal membership and professional authority.
5. Create pilot client.
6. Create Formwork intake using complete project inputs.
7. Create proposal and price.
8. Approve proposal as authorized human Principal.
9. Accept proposal and open project.
10. Start and complete delivery task.
11. Create evidence bundle.
12. Draft deliverable.
13. Review deliverable with professional authority.
14. Issue deliverable.
15. Create and issue invoice.
16. Record payment status.
17. Provision bounded AI worker if assistive support is needed.
18. Publish private trusted-network listing/capacity signal if pilot collaboration is needed.
19. Generate observatory snapshot.
20. Review audit and event trail.

## Required Formwork intake fields

- project name;
- site location;
- client organization;
- client contact name/email;
- structure type;
- formwork element type;
- height;
- length or area;
- concrete grade;
- available drawings;
- deadline;
- required deliverables.

## Professional boundaries

AI may assist with extraction, drafting, routing, checking, and summarizing.

AI must not:

- approve regulated work;
- sign or seal documents;
- invent engineering conclusions;
- claim manufacturer-specific design validity without licensed source data;
- bypass human review.

## Pilot evidence expectations

- intake completeness;
- document revision consistency;
- unit consistency;
- positive geometry values;
- risk classification completeness;
- approval before issue;
- manufacturer/source provenance note;
- calculation input schema validity.

## Pilot success signal

The pilot is successful when the operator can complete the whole service loop without reading raw JSON, and the audit trail explains who did what, under what authority, and with what evidence.
