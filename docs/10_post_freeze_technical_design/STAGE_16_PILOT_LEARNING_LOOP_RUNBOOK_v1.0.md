# Stage 16 - Pilot Learning Loop Runbook v1.0

## Operator rhythm

1. Run a pilot workflow.
2. Capture feedback from the principal, operator, or observer.
3. Record acceptance review against pilot criteria.
4. Convert material gaps into improvement items.
5. Prioritize `P0`/`P1` items before wider pilot expansion.
6. Mark improvements done only after product change, retest, or explicit acceptance.

## Priority guidance

| Priority | Meaning |
|---|---|
| `P0` | Blocks safe pilot continuation. |
| `P1` | Blocks pilot expansion or affects trust/compliance. |
| `P2` | Important workflow/UX improvement. |
| `P3` | Nice-to-have refinement. |

## Acceptance rule

Pilot acceptance is not a vague feeling. It must be recorded with criteria, decision, notes, and evidence references where available.
